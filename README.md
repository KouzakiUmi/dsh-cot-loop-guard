# CoT 循环守卫：水坝式流式输出治理

中文 | [English](README.en.md)

**这是技术参考仓库，不是可安装插件、通用补丁包或 DSH 发行版。**

本仓库记录一个在 DeepSeek Harness（DSH）中实现的流式推理循环守卫：正常输出即时放行；发现疑似重复后才暂存后续输出；证据回落则释放，确认持续停滞则只取消当前模型调用，保存安全前缀，并在有限预算内要求模型换一种方式继续。

CoT 在这里仅指适配器实际提供的可见 reasoning 输出。它不是读取模型内部状态、判断思考是否正确或识别所有语义循环的能力。

## 核心思路

```text
适配器确认 editable-plain
          |
原始 reasoning 字符流
          |
可见停滞检测器 —— 疑似才蓄水，回落则放行，确认才丢弃未提交尾巴
          |
精确副本过滤器 —— 只删除已有原文证据的重复副本
          |
已接纳输出 —— 同时驱动实时显示、持久记录和后续请求
```

两种机制不能混为一谈：

- **精确副本过滤**：可以删除有证据的重复副本，但不能把数字、标识符、否定词变化当作相同内容。
- **可见停滞截断**：对“短句反复出现、长句略变”的循环，允许停止调用并丢弃尚未提交的疑似尾巴；它不是模糊去重，不会拼接改写已显示的文本。

## 水坝的四种可见状态

| 状态 | 真实触发条件 | 呈现含义 |
|---|---|---|
| 疑似缓冲 | 完整观察窗首次同时满足重复证据 | 正在缓冲检查，不是已经失败 |
| 恢复/保护放行 | 观察回落，或工具保护路径主动释放 | 释放尚未提交的文本；阶段标签不总能证明重复率下降 |
| 屏障放行 | 围栏、非推理事件或结算要求释放 | 只说明缓冲被释放，不宣称重复率回落 |
| 确认截断 | 连续确认或持有上限处仍有重复证据 | 立即通知正在截断；清理完成后才结算和续跑 |

通知更新同一条状态行，不逐 token 刷屏。疑似/放行状态是实时呈现，不写进模型输入；真正的截断结算和续跑提示有持久记录。活动调用的最近阶段进入重连快照，因此重新打开仍在运行的会话时可以恢复当前状态，而不会伪造已经结束的探测历史。

## 参数概览

可见停滞检测的默认值：

| 参数 | 默认值 |
|---|---:|
| 初始观察窗 | 1024 UTF-16 码元 |
| 最大保留窗口 | 8192 UTF-16 码元 |
| 观察间隔 | 128 UTF-16 码元 |
| 最少完整句子单元 | 16 |
| 重复单元数量占比 | ≥ 0.5 |
| 重复单元字符占比 | ≥ 0.15 |
| 字符片段长度 / 覆盖阈值 | 8 / ≥ 0.6 |
| 连续确认 / 连续恢复 | 3 / 2 次观察 |

**8192 不是“必须等满才截断”，也不是整个应用的内存上限。** 精确副本检测器还有自己的窗口和暂存空间。连续确认可以提前截断。

自动续跑默认最多 **1 次/Agent/turn/策略实例**；设成 3 是一种配置选择，不是源码默认值。普通工具重复提醒与输出编辑也是两项独立能力，挂载工具提醒不代表已经启用 reasoning 输出编辑。

## 重要边界

- 未明确声明可编辑重放、签名、加密或不透明推理内容：不启用输出编辑，不能靠丢签名伪装兼容。
- 用户/父级取消、清理失败或策略卸载：不得靠自动续跑复活任务。
- 完整真实工具块之后：禁止由重复检测随意取消调用，另用工具结算预算约束；不执行未结算的部分工具调用。
- 合法重复和会自行恢复的重复仍可能被拦截；这里不宣称零误报或固定响应时延。
